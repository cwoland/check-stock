# CheckStock

Веб-прототип складского учёта. Показывает остатки по артикулам и складам фулфилмента (ФФ), резервы FBS, товар в пути и историю движений.

## Запуск

Нужны [uv](https://docs.astral.sh/uv/) и PostgreSQL. На macOS можно запустить сервер в Postgres.app. Команды ниже предполагают, что локальный сервер слушает порт 5432 и принимает подключение от текущего пользователя.

Выполните из корня репозитория:

```bash
uv python install 3.15
uv sync --locked
pg_isready -h localhost -p 5432
createdb -h localhost -p 5432 check_stock
export DATABASE_URL=postgresql+psycopg://localhost:5432/check_stock
uv run alembic upgrade head
uv run python -m api.seed
uv run uvicorn api.main:app --host 127.0.0.1 --port 8000
```

Базу нужно создать один раз. Если команды PostgreSQL отсутствуют в PATH при установленном Postgres.app, выполните `export PATH="/Applications/Postgres.app/Contents/Versions/latest/bin:$PATH"`.

Откройте [экран остатков](http://127.0.0.1:8000/) или [документацию API](http://127.0.0.1:8000/docs). Загрузчик демоданных можно запускать повторно: он учитывает каждый демонстрационный приход один раз.

| Артикул | Товар | Север | Юг |
| --- | --- | ---: | ---: |
| SKU-101 | Органайзер | 10 | 6 |
| SKU-102 | Контейнер | 5 | 0 |
| SKU-103 | Корзина | 0 | 4 |


## Как устроен учёт

- FastAPI обслуживает JSON API и отдаёт HTML-страницу. Формы вызывают те же API, которые проверяются интеграционными тестами.
- SQLAlchemy хранит физический остаток и резерв по паре «артикул + ФФ». Доступно = физический остаток − резерв. Ограничения PostgreSQL запрещают отрицательный резерв и резерв сверх физического остатка.
- Списание, зачисление и запись операции выполняются в одной транзакции. UUID позволяет повторить запрос создания, а блокировки строк защищают от двойной приёмки. История показывает названия складов на момент операции.
- Перемещение числится в пути от отправки до приёмки. FBS сначала резервирует товар, затем освобождает резерв при отмене или списывает товар при отправке. Для отправленного FBS конечный статус прототипа — «в пути к клиенту». FBO списывает товар при отправке и отмечает его принятым на маркетплейсе после подтверждения.
- Архивация закрывает новый приход, резерв и входящую отправку на ФФ. Остаток можно вывезти с архивного ФФ. Очистка проверяет срок при запуске API и каждую минуту. После 30 дней запись удаляется из списка складов, а исходный ID и название сохраняются для остатков и истории. Уже отправленное перемещение можно принять на исторический ID.
- Экран читает остатки и движения в одном снимке PostgreSQL. Миграции Alembic разворачивают схему с нуля и обновляют существующую базу.
